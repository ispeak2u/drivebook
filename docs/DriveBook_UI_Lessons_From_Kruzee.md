# DriveBook UI Lessons From Kruzee

## 1. What DriveBook Should Emulate Conceptually

- Trust-first marketplace design: show verified instructors, reviews, badges, and safety assurances throughout the booking flow.
- Clear public pricing before signup.
- Location-aware onboarding so students only see relevant instructors.
- Mobile-first booking flow with one obvious next step at a time.
- Strong reassurance for nervous drivers, newcomers, and road test repeaters.
- Review and testimonial patterns that answer practical student concerns.
- Emphasis on online scheduling as a major value proposition.

## 2. What DriveBook Should Do Differently

- Keep the first MVP tightly focused on Toronto instead of presenting many regions.
- Let students browse a small set of instructor cards before forcing a full booking funnel.
- Make instructor comparison more central than school/course branding.
- Show availability previews earlier.
- Keep package/pricing presentation simple and consistent.
- Avoid a hard context switch between marketing site and app if possible.
- Make cancellation, pending approval, and instructor acceptance states visible before checkout.

## 3. Features That Matter for MVP

- Home page with strong Toronto-specific positioning.
- Student signup.
- Instructor signup.
- Instructor profile cards with verification, areas served, languages, vehicle, hourly rate, experience, and specialties.
- Search instructors by Toronto area, lesson type, language, transmission, and availability.
- Booking request flow with pending status.
- Instructor accept/decline flow.
- Verified review system tied to completed bookings.
- Public trust summary: average rating, total reviews, verified lesson badge.
- Simple cancellation policy text.

## 4. Features to Save for Phase 2

- Payment plans.
- Full online course / e-learning portal.
- Insurance-discount education workflows.
- Rich progress reporting.
- SMS/email reminder automation.
- Advanced schedule optimization.
- Multi-city expansion.
- Parent-specific portal.
- Deep instructor performance analytics.
- Admin tools beyond approval, review moderation, and dispute basics.

## 5. Suggested DriveBook User Flow Inspired by the Research

1. Home page
   - Toronto-first hero.
   - Primary CTA: Find an instructor.
   - Secondary CTA: Become an instructor.
   - Trust strip with verified instructors, completed lessons, average review score, and safe booking policy.

2. Location and goal
   - Ask for pickup area or Toronto neighborhood.
   - Ask learning goal: G2, G, nervous driver, newcomer, refresher.
   - Keep this lightweight and skippable for browsing.

3. Instructor search
   - Show instructor cards with photo placeholder, hourly rate, language, areas served, vehicle, specialties, rating, and next available slots.
   - Include verified badge and review count.

4. Instructor profile
   - Show full bio, badges, reviews, cancellation policy, vehicle/safety details, and available lesson types.
   - CTA: Request lesson.

5. Booking request
   - Select date/time.
   - Enter pickup location.
   - Confirm lesson request.
   - Status starts as pending until instructor accepts.

6. Student dashboard
   - Show pending, accepted, declined, completed bookings.
   - Show next lesson and cancellation policy.

7. Instructor dashboard
   - Show booking requests.
   - Accept or decline.
   - Surface profile completeness and review health.

8. Review after completion
   - Only completed bookings can receive reviews.
   - Review dimensions: overall, punctuality, communication, teaching clarity, vehicle cleanliness/safety, recommendation, written review.

## Product Principle

DriveBook should learn from Kruzee's trust density and mobile booking clarity, but differentiate through a more transparent instructor marketplace experience for Toronto students.
